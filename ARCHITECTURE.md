## Purpose

VS Code extension that runs a per-window MCP HTTP server on a random loopback port, letting Claude Code, Codex, or any MCP client in the integrated terminal query VS Code state (diagnostics, git status, etc.) from the exact window they're running in. Primary users: AI coding assistants in VS Code terminals. Hardest constraints: (1) loopback-only security, (2) stateless sessions — concurrent clients never share MCP state, (3) no VS Code imports in tests — all access behind `VscodeAdapter`.

## Repository map

- `src/` — extension source (TypeScript, bundled via esbuild to `dist/extension.js`).

  - `src/server/` — HTTP server and MCP protocol wiring.

- `arch/` — cross-cutting architecture detail files.
- `docs/` — technical documentation, specs, plans, tasks.

## Runtime flow

1. **Activation** — `src/extension.ts` runs on `onStartupFinished`, creates adapter → tools → stateless MCP handler.
2. **Port selection** — `configWriter` checks `.vscode/mcp.json` and `.mcp.json` for a pinned port; otherwise random.
3. **HTTP server** — `src/server/httpServer.ts` listens on `127.0.0.1:<port>`, validates loopback, parses body.
4. **Stateless MCP dispatch** — `src/server/mcpServer.ts` builds a fresh `McpServer` + transport per request, registers tools via `registry.ts`.
5. **Tool execution** — tool handler delegates to `McpTools`, which calls `VscodeAdapter`, applies logic, returns text.
6. **Client discovery** — `VSCODE_MCP_URL` injected into terminals via `EnvironmentVariableCollection`; optionally registered with `registerMcpServerDefinitionProvider` (VS Code ≥1.116).
